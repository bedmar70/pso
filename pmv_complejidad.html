Complexity Governor

Gobernar complejidad antes de herramientas

¿Qué es esto?

Complexity Governor no es un gestor de tareas.
Es un sistema para decidir:
  • qué es realmente complejo
  • cuánta complejidad puede sostener la organización
  • quién decide
  • cuándo algo está cerrado

¿Cuándo se usa?

Cuando:
  • todo parece urgente
  • hay muchas cosas abiertas y pocas cerradas
  • las decisiones se reabren
  • las herramientas no “cuajan”

Cómo usar el sistema (orden obligatorio)

  1. Clasificar → entender qué tipo de problema es
  2. Intake → decidir si entra o no
  3. WIP → limitar cuántos problemas complejos hay activos
  4. Decisiones → asignar DRI y caducidad
  5. Rituales → priorizar y cerrar
  6. Salida → el sistema ya funciona sin el consultor
Regla de oro:
Nada complejo se ejecuta sin pasar por Intake y WIP.

1️⃣ Clasificación

Aquí se trae cualquier cosa que llegue a la empresa (email, WhatsApp, idea, urgencia). El objetivo no es resolverla, sino clasificarla correctamente.
Pregúntate:
  • ¿Está cubierto por una regla?
  • ¿Cruza áreas?
  • ¿Es reversible?
  • ¿Requiere decisión o solo ejecución?

(Aquí viviría el asistente de clasificación que ya has visto en la versión anterior)

2️⃣ Intake

Todo pasa por aquí. Nada entra directamente al sistema.
Decisiones posibles:
  • ENTRA → pasa a WIP
  • ESPERA → backlog consciente
  • NO ENTRA → se descarta explícitamente
  • OPERATIVO → se resuelve sin contaminar WIP

3️⃣ WIP – Problemas complejos activos

Aquí solo viven problemas complejos.
Si el WIP está lleno, algo debe salir antes de que algo entre.
Si todo está en WIP, entonces nada lo está.

4️⃣ Decisiones

Una decisión sin DRI no existe.
Una decisión compleja sin caducidad se convierte en dogma.
Tipos:
  • Operativa → ejecutar
  • Táctica → ajustar reglas/capacidad
  • Sistémica → cambiar el marco

5️⃣ Rituales

Los rituales sostienen el sistema sin heroicidad.
Ejemplos:
  • Intake semanal (30 min)
  • Priorización operativa
  • Cierre semanal
Si un ritual se cancela “por urgencia”, el sistema está en riesgo.

Salida del sistema

Esta fase termina cuando:
  • el equipo clasifica sin el consultor
  • el Intake se respeta
  • el WIP no se rompe
  • las decisiones se cierran
Si el sistema no funciona sin ti, no ha terminado.
